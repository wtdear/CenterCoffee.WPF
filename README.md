# Центр кофе — WPF-приложение для ИП Миргородский

Учётное приложение кофейни «Центр кофе». Текущий этап: **главное окно и система контроля склада**.
Остальные модули вынесены в стадию «В разработке» и показаны в интерфейсе как заглушки —
бизнес-логика по ним намеренно не реализована.

## Что уже работает

- **Главное окно**: боковая навигация по разделам, шапка с названием раздела и датой,
  карточка владельца, отметки «скоро» у будущих модулей.
- **Склад**:
  - список складских позиций с поиском по названию;
  - фильтр «Только ниже минимума»;
  - показатели: количество позиций, позиции ниже минимума, отсутствующие позиции,
    суммарная стоимость запасов;
  - добавление и редактирование позиции (название, единица измерения, начальный остаток,
    минимальный остаток, закупочная цена);
  - приход и списание с комментарием и контролем остатка;
  - цветовые статусы: «В норме», «Ниже минимума», «Нет в наличии»;
  - история операций по выбранной позиции или по всему складу.

## Архитектура

Решение разделено на слои. Зависимости направлены внутрь: UI зависит от Application,
Application — от Domain; Infrastructure реализует контракты Application/Domain.

```
src/
├── CenterCoffee.Domain/          # Сущности, бизнес-правила, интерфейсы репозиториев
│   ├── Common/                   # Entity, DomainException, Guard
│   ├── Warehouse/                # Ingredient, StockMovement, MeasurementUnit
│   ├── Employees/                # Employee, EmployeeRole
│   ├── Menu/                     # Category, Product, RecipeItem
│   ├── Orders/                   # Order, OrderItem, статусы (на будущее)
│   └── Repositories/             # IRepository, IIngredientRepository и др.
│
├── CenterCoffee.Application/     # Сценарии использования (use cases)
│   ├── Abstractions/             # IWarehouseService, IUnitOfWork, WarehouseSummary
│   └── Services/                 # WarehouseService
│
├── CenterCoffee.Infrastructure/  # Реализация хранения
│   └── Persistence/              # AppData, JsonDataStore, JsonUnitOfWork, репозитории
│
└── CenterCoffee.WPF/             # Представление (MVVM)
    ├── Mvvm/                     # ObservableObject, RelayCommand, DialogViewModel
    ├── ViewModels/               # MainViewModel, WarehouseViewModel, строки таблиц
    ├── Views/                    # WarehouseView, ComingSoonView
    ├── Windows/                  # Диалоги добавления/операций
    ├── Converters/               # Конвертеры значений для XAML
    ├── Services/                 # IDialogService и реализация
    ├── Resources/Theme.xaml      # Кофейная тема и стили
    ├── App.xaml(.cs)             # Точка входа, composition root
    └── MainWindow.xaml(.cs)      # Оболочка приложения
```

### Принципы, которые соблюдены

- **SRP**: сущности хранят инварианты, сервисы — сценарии, репозитории — доступ к данным,
  модели представления — состояние экрана и команды.
- **OCP**: новый модуль добавляется как новый сервис/ViewModel/View, без переписывания склада.
- **LSP/ISP**: узкие интерфейсы (`IWarehouseService`, `IIngredientRepository` и т. д.).
- **DIP**: WPF-слой зависит от `IWarehouseService`, а не от JSON-хранилища.
- **Инкапсуляция**: остаток `Ingredient` меняется только через `Receive`/`WriteOff`,
  изменения валидируются в домене (`Guard`, `DomainException`).
- **MVVM**: код-behind окон содержит только подключение `CloseRequested`, бизнес-логики нет.

### Хранение данных

- Локальный JSON-файл: `%APPDATA%\CenterCoffee\data.json`.
- Файл создаётся при первом сохранении. **База не заполняется сидами, демо-данными
  или тестовыми записями** — заказчик начинает с пустого склада.
- Путь можно переопределить переменной окружения `CENTERCOFFEE_DATA_PATH`
  (удобно для тестов и портативного запуска).
- Запись атомарная: сначала во временный файл, затем замена основного.
- Реализация скрыта за `IUnitOfWork`; при необходимости JSON легко заменить на SQLite/SQL Server.

## Сборка и запуск

Требования: Windows, .NET Framework 4.7.2, Visual Studio 2022/2026 с workload
«Разработка классических приложений .NET».

1. Открыть `CenterCoffee.WPF.slnx` в Visual Studio.
2. Выбрать конфигурацию `Debug` и запустить `CenterCoffee.WPF` (F5).

Сборка из консоли (старый формат WPF-проекта требует MSBuild из Visual Studio,
`dotnet build` для него не подходит):

```powershell
& "C:\Program Files\Microsoft Visual Studio\18\Community\MSBuild\Current\Bin\MSBuild.exe" `
  "CenterCoffee.WPF.slnx" /v:m
```

## Проверка сценария склада

1. Запустить приложение — откроется пустой склад.
2. Нажать «+ Добавить позицию», заполнить название, единицу измерения, начальный и
   минимальный остаток, закупочную цену.
3. Через карточку позиции выполнить «Приход» или «Списание».
4. Убедиться, что остаток, стоимость запасов и история операций обновились.
5. Установить остаток ниже минимума — позиция подсветится статусом «Ниже минимума»,
   счётчик в шапке увеличится.
