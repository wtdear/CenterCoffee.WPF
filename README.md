# Центр кофе — WPF-приложение для ИП Миргородский

Учётное приложение кофейни «Центр кофе».

**Текущая версия — 0.1.0.** В неё входят главное окно, склад, отчёты по складу,
целостность данных и резервные копии. Продажи, заказы, закупки, меню и сотрудники
показаны в интерфейсе заглушками «В разработке» — их бизнес-логика намеренно не
реализована. Номер версии относится к готовому модулю склада, а не ко всей системе
из ТЗ.

## Установка

Готовый установщик лежит в репозитории — скачайте файл и запустите:

**https://github.com/wtdear/CenterCoffee.WPF/raw/main/release/CenterCoffee.Setup.msi**

1. Запустить `CenterCoffee.Setup.msi` (Windows запросит права администратора).
2. Выбрать папку установки — по умолчанию `C:\Program Files\CenterCoffee`.
3. После установки запускать через ярлык «Центр кофе» в меню «Пуск».

Требования: Windows 10/11 с .NET Framework 4.7.2 или новее. Установщик проверяет
framework и сообщает, если его не хватает.

Данные приложения хранятся отдельно от установки, в
`%APPDATA%\CenterCoffee\data.json`, и при обновлении не затрагиваются.
Перенос данных на другое устройство — через раздел «Целостность»
(создать копию `.json` на старом, восстановить на новом).

Обновление: запустить установщик новой версии поверх старой — она заменит
предыдущую и сохранит данные. Удаление: «Параметры → Приложения → Центр кофе».

Установщик не подписан цифровой подписью, поэтому при первом запуске Windows
может предупредить о неизвестном издателе — это ожидаемо.

Контрольная сумма последней сборки:

```text
SHA-256: 2BD9983CA055433C78C45933F0750BE4B2D71C1BA669ABEA05BCED4D3CDBAF7F
```

## Известные ограничения версии 0.1.0

- Продажи, заказы, закупки, меню и сотрудники не реализованы (заглушки в меню).
- Нет автоматических тестов: проверка склада пока ручная, по сценариям ниже.
- Хранение — локальный JSON-файл, не база данных; расчёт себестоимости по
  закупкам и FIFO не реализован, стоимость запасов — оценка по закупочной цене.
- Не определено правило для остатка, равного минимуму: домен считает такую позицию
  дефицитной (`остаток <= минимум`), а подпись в интерфейсе — «Ниже минимума».
- Единицы закупки и пересчёты не определены; рецептуры и списание по продаже
  отсутствуют.

## Что уже работает

- **Главное окно**: боковая навигация по разделам, шапка с названием раздела и датой,
  карточка владельца, отметки «скоро» у будущих модулей.
- **Склад**:
  - список складских позиций с поиском по названию;
  - фильтр «Только ниже минимума»;
  - показатели: количество позиций, позиции ниже минимума, отсутствующие позиции,
    суммарная стоимость запасов;
  - добавление и редактирование позиции (название, единица измерения, начальный остаток,
    минимальный остаток, закупочная цена);
  - приход и списание с комментарием и контролем остатка;
  - цветовые статусы: «В норме», «Ниже минимума», «Нет в наличии»;
  - история операций по выбранной позиции или по всему складу.
- **Отчёты по складу** (раздел «Отчёты»):
  - вкладка «Остатки»: позиции на дату, минимальные остатки, стоимость по закупочной
    цене и статусы;
  - вкладка «Обороты»: остаток на начало, приход, списание и остаток на конец
    по каждой позиции за выбранный период;
  - вкладка «Дефицит»: позиции на минимуме или ниже, рекомендуемое количество
    к закупке и оценка стоимости докупки;
  - вкладка «Движение»: журнал прихода, списания и начальных остатков за период;
  - быстрые пресеты периода: «Сегодня», «Вчера», «Неделя» (с понедельника),
    «Месяц» (с 1-го числа), «Квартал» (с начала квартала) и «За всё время»
    (от первой операции в истории);
  - экспорт текущего отчёта в Excel (`.xlsx`) с выбором файла: оформленная таблица
    с заголовком, сводкой над ней, ширинами колонок, закреплённой шапкой,
    автофильтром и окраской строк по статусу;
  - все показатели считаются в `IWarehouseReportService`, а не в UI;
  - стоимость запасов и докупки — оценка по закупочной цене карточки, **не**
    FIFO и не себестоимость: пока нет закупочных документов, как rental
    себестоимость не нормирована.
- **Целостность и резервные копии**:
  - состояние локального файла: существует ли он, версия формата, дата изменения,
    количество позиций и операций;
  - проверка целостности: повреждение файла, неподдерживаемая версия, операции без
    позиции, некорректные значения, повторяющиеся названия, расхождение остатка
    с последней операцией;
  - создание резервной копии отдельным файлом `.json` с датой в имени; копия сразу
    проверяется на читаемость;
  - восстановление из копии с предварительной проверкой, подтверждением и
    страховочной копией текущего файла.

## Архитектура

Решение разделено на слои. Зависимости направлены внутрь: UI зависит от Application,
Application — от Domain; Infrastructure реализует контракты Application/Domain.

```
src/
├── CenterCoffee.Domain/          # Сущности, бизнес-правила, интерфейсы репозиториев
│   ├── Common/                   # Entity, DomainException, Guard
│   ├── Warehouse/                # Ingredient, StockMovement, MeasurementUnit
│   ├── Employees/                # Employee, EmployeeRole
│   ├── Menu/                     # Category, Product, RecipeItem
│   ├── Orders/                   # Order, OrderItem, статусы (на будущее)
│   └── Repositories/             # IRepository, IIngredientRepository и др.
│
├── CenterCoffee.Application/     # Сценарии использования (use cases)
│   ├── Abstractions/             # IWarehouseService, IUnitOfWork, WarehouseSummary
│   └── Services/                 # WarehouseService
│
├── CenterCoffee.Infrastructure/  # Реализация хранения
│   └── Persistence/              # AppData, JsonDataStore, JsonUnitOfWork, репозитории,
│                                 # DataSchema, проверка целостности и резервные копии
│
└── CenterCoffee.WPF/             # Представление (MVVM)
    ├── Mvvm/                     # ObservableObject, RelayCommand, DialogViewModel
    ├── ViewModels/               # MainViewModel, WarehouseViewModel, строки таблиц
    ├── Views/                    # WarehouseView, ComingSoonView
    ├── Windows/                  # Диалоги добавления/операций
    ├── Converters/               # Конвертеры значений для XAML
    ├── Services/                 # IDialogService и реализация
    ├── Resources/Theme.xaml      # Кофейная тема и стили
    ├── App.xaml(.cs)             # Точка входа, composition root
    └── MainWindow.xaml(.cs)      # Оболочка приложения
```

### Принципы, которые соблюдены

- **SRP**: сущности хранят инварианты, сервисы — сценарии, репозитории — доступ к данным,
  модели представления — состояние экрана и команды.
- **OCP**: новый модуль добавляется как новый сервис/ViewModel/View, без переписывания склада.
- **LSP/ISP**: узкие интерфейсы (`IWarehouseService`, `IIngredientRepository` и т. д.).
- **DIP**: WPF-слой зависит от `IWarehouseService`, а не от JSON-хранилища.
- **Инкапсуляция**: остаток `Ingredient` меняется только через `Receive`/`WriteOff`,
  изменения валидируются в домене (`Guard`, `DomainException`).
- **MVVM**: код-behind окон содержит только подключение `CloseRequested`, бизнес-логики нет.

### Хранение данных

- Локальный JSON-файл: `%APPDATA%\CenterCoffee\data.json`.
- Файл создаётся при первом сохранении. **База не заполняется сидами, демо-данными
  или тестовыми записями** — заказчик начинает с пустого склада.
- Путь можно переопределить переменной окружения `CENTERCOFFEE_DATA_PATH`
  (удобно для тестов и портативного запуска).
- Запись атомарная: сначала во временный файл со сбросом на диск, затем замена основного.
- Документ содержит поле `schemaVersion` (текущая версия — `1`). Если файл сохранён
  без этого поля, он читается, но помечается как старая версия и приводится к текущей
  при следующем сохранении.
- **Повреждённый файл не заменяется пустой базой.** При старте приложение показывает
  сообщение и не изменяет файл, чтобы потеря данных не выглядела как чистый старт.
  Файл с версией формата новее поддерживаемой также не открывается.
- Реализация скрыта за `IUnitOfWork`; при необходимости JSON легко заменить на SQLite/SQL Server.

### Резервные копии

- Раздел «Целостность» → «Создать резервную копию» записывает **отдельный файл**
  `data-<ГГГГММДД-ЧЧММСС>.json` в выбранную папку. Прошлые копии не перезаписываются.
- Сразу после записи копия перечитывается и проверяется; непроверенный файл удаляется.
- «Восстановить данные» сначала проверяет выбранный файл, показывает его версию и
  содержимое для подтверждения, затем заменяет рабочий файл атомарно.
- Перед заменой рядом с локальной базой сохраняется страховочная копия
  `*.before-restore-<дата>.json`, поэтому восстановление можно отменить вручную.
- Восстановление запрещено при повреждённом и при неподдерживаемом файле данных.
- После успешного восстановления экран склада перечитывает данные. Если файл заменён,
  но перечитать его не удалось, работа со складом блокируется до перезапуска:
  сохранение старых данных из памяти затёрло бы восстановленные.

## Сборка установщика и релиз-пакета

Скрипт собирает Release-версию приложения и MSI-установщик (WiX Toolset v6,
скачивается автоматически при восстановлении проекта `installer/`), затем кладёт
готовый файл в `release/`:

```powershell
powershell -ExecutionPolicy Bypass -File tools\package-release.ps1 -Version 0.1.0
```

Скрипт печатает SHA-256 готового файла и пересобирает MSI принудительно: смена
`-Version` сама по себе не считается изменением входных данных, и без `/t:Rebuild`
в `release/` попал бы установщик от предыдущей версии.

Ключ `-Portable` дополнительно копирует exe и dll в корень решения и создаёт
ярлык на рабочем столе — это локальный запуск без установки, в git такие копии
не попадают.

Порядок выпуска новой версии:

1. Собрать: `tools\package-release.ps1 -Version 0.2.0`.
2. Закоммитить обновлённый `release\CenterCoffee.Setup.msi` вместе с изменениями.
3. Пересчитать контрольную сумму в README (`Get-FileHash ... -Algorithm SHA256`).
4. Поставить тег: `git tag -a v0.2.0 -m "..."` и запушить его.

Установщик заменяет предыдущую версию при установке поверх и удаляет файлы при
удалении программы. Исходники установщика (`installer/`) остаются в репозитории,
чтобы MSI можно было собрать заново и изменить.

## Проверка сценария склада

1. Запустить приложение — откроется пустой склад.
2. Нажать «+ Добавить позицию», заполнить название, единицу измерения, начальный и
   минимальный остаток, закупочную цену.
3. Через карточку позиции выполнить «Приход» или «Списание».
4. Убедиться, что остаток, стоимость запасов и история операций обновились.
5. Установить остаток ниже минимума — позиция подсветится статусом «Ниже минимума»,
   счётчик в шапке увеличится.

## Проверка сценария резервной копии

1. Открыть раздел «Целостность». На новой установке — «Файл данных ещё не создан»,
   кнопка копии недоступна.
2. Добавить позицию на складе и вернуться — состояние станет «Данные в порядке»,
   версия формата `1`, отобразятся количество позиций и операций.
3. «Создать копию» → выбрать папку. В папке появится `data-<дата>.json`, в подсказке
   будет полный путь. Повторное нажатие создаёт копию с новым именем.
4. Изменить данные на складе (например, списать), затем «Восстановить данные» →
   выбрать копию. В подтверждении проверить содержимое и нажать «Восстановить данные».
5. Убедиться, что склад вернулся к состоянию на момент копии, рядом с базой появился
   файл `*.before-restore-*.json`.
6. Негативные проверки: выбрать повреждённый `.json` — восстановление отклоняется;
   испортить `data.json` в блокноте — при запуске показывается сообщение, файл не
   перезаписывается.
